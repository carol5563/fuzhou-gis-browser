## Day 2：接入天地图底图（踩坑实录）

### 坑 1：裸 URL 只带 tk → 400 Bad Request

- 天地图走的是 **WMTS**（OGC 标准协议），不是高德那种野路子 XYZ 接口，参数必须报全：
  `SERVICE=WMTS&REQUEST=GetTile&VERSION=1.0.0&LAYER=图层名&STYLE=default&TILEMATRIXSET=w&FORMAT=tiles&TILEMATRIX={z}&TILEROW={y}&TILECOL={x}&tk=密钥`
- **400 vs 404**：404 是地址找不到；400 是地址对了但参数不合法，服务器看不懂你的请求

### 坑 2：`_c` 和 `_w` 选错 → 地图变形错位

- 每个图层都有两套金字塔：`_w` = Web 墨卡托（3857）；`_c` = CGCS2000 经纬度直投（EPSG:4490，≈ 4326，差厘米级）
- **瓦片的坐标系必须和 View 的 projection 匹配**：我的 View 没设 projection，默认 3857（`fromLonLat` 就是证据），所以用 `vec_w` / `cva_w`

### 坑 3：图层名在 URL 里出现两次，改一处忘一处 → 返回占位图

- 路径 `/vec_w/` 改对了，但 `LAYER=img` 是从官方文档示例原样抄的忘了改 → 服务器返回一张写着「此级别下，该区域无影像」的占位图
- 阴险之处：HTTP 状态码是 **200**，Network 面板看不到红色报错，图片本身就是"错误提示"
- 规律总结（第 4 次踩同类坑）：**同一个信息要写两遍的地方就是 bug 高发区**，拼 URL 先扫一遍成对出现的值是否一致

### TILEMATRIXSET 是什么（拆词：Tile Matrix Set = 瓦片·矩阵·集）

| 概念 | 是什么 | 对应我熟的 |
|---|---|---|
| Tile | 一张 256×256 瓦片 | 就是那张图 |
| TileMatrix | 某一级别下所有瓦片排成的矩阵 | 金字塔的某一层，`TILEMATRIX={z}` |
| TileMatrixSet | 所有级别矩阵的集合 | **整座瓦片金字塔** |

- `TILEMATRIXSET=w` 人话："我要用墨卡托切法的那座金字塔"
- 对照关系：`TILEMATRIX={z}`、`TILEROW={y}`、`TILECOL={x}` —— z/x/y 的西装版

### 天地图速查

- 域名：`t0` 到 `t7` 八个子域名，可写 `t{0-7}`（同高德 `webst0{1-4}` 套路）
- 矢量底图 `vec` + 注记 `cva`；影像底图 `img` + 注记 `cia`；路径和 LAYER 两处同步改
- 用 `https`，别用 `http`（以后部署到 https 站点会被浏览器拦）
- 天地图是 CGCS2000，≈ WGS84，**不加密不偏移**；和高德（GCJ-02）坐标不能直接混用

day3:
同center叠加（控制变量），高德（GCJ-02）当底图+天地图（CGCS2000(~WGS84)）上层opacity:0.5，肉眼可见错位几百米。原因：同一坐标在不同坐标系中渲染在金字塔瓦片中的位置不一样。opacity是TileLayer的options，不是source XYZ的options（放错会静默忽略）。
**Day 3 实验结果**：
- WGS84 坐标打点（[119.388263, 26.027506]）→ 切换底图：
- 天地图底图（CGCS2000）：红点落在某小区内 ← 真实位置
- 高德底图（GCJ-02）：红点偏到路旁 ← 视觉偏移几百米
- 结论：底图坐标系与数据坐标系必须匹配，否则位置整体漂移

## Day 3 踩坑（打点实验）

### 坑 4：`.crdownload` 锁住 Vite → `EBUSY`

- 现象：`pnpm dev` 启动报错 `EBUSY: resource busy or locked, watch '...未确认 52489.crdownload'`
- 原因：`.crdownload` 是 Chrome 下载临时文件（"未确认"= 还没下载完/中断了），Vite 的 chokidar 要 watch `public/` 下所有文件，遇到被锁的文件就崩
- 解决：删 `public/` 下未完成的 `.crdownload`；以后下载文件**别直接下到项目目录**，先下到"下载"文件夹再手动挪

### 坑 5：报 `401 Unauthorized` → 示例代码原样拷贝

- 现象：Network 面板出现 `https://maps.gnosis.earth/ogcapi/...` 瓦片请求 401
- 原因：从 OL Icon 示例里原样拷了 `OGCMapTile` 源（指 `maps.gnosis.earth`），那是示例的演示服务器，现在加了访问限制
- 解决：删掉那个 `rasterLayer`（反正不属于我实验需要）
- 教训：**抄示例时多看一眼，这一行是为了解决我的问题还是示例自己的问题？**

### 坑 6：Icon 不显示点 → SVG fill 不是 currentColor

- 现象：换了 `Icon({ src: 'dot.svg', scale: 0.2 })` 后，地图上什么也看不到
- 原因：dot.svg 里的 circle 写的是 `fill="#ffffff"`（固定白色）+ 黑色描边，20×20 原尺寸，scale 0.2 后变 4 像素
  - 一个 4 像素的**白点**几乎看不见
  - OL 的 Icon `color` 参数只对 `fill="currentColor"` 生效，固定颜色不会被你传的红/蓝染色
- 验证方法：**临时换成 CircleStyle 验证点画没画**（不用图片、一定画得出来）→ 出来了说明点是画了、是 Icon 的问题
- 结论：学习阶段不纠结这个，用 CircleStyle 先跑通实验；以后真要用图标选 `fill="currentColor"` 的 SVG

### 概念澄清：VectorSource 到底是"数据来源"还是"Feature 容器"？

- **都是，同一件事**。Source 永远是"图层的数据从哪来"，区别只是"数据长什么样"：
  - `XYZ` Source → 数据 = 瓦片图片的 URL
  - `VectorSource` → 数据 = Feature（点/线/面）
- 对 Layer 来说，"从这来"；对你写代码来说，"往里塞 Feature"

### 检索词选择：在 OL Examples 页搜什么

- 搜 `Point` → 出来的是几何操作（面积/最近点），不是"打个标记"
- 搜 `Icon` → 出来的是"往地图上放个图标标记"← **要的就这个**
- 搜 `Vector` → 出来的是"添加矢量要素"通用模式
- 原则：例标题按**你最终看到的效果**命名，不按底层 API 名命名

- 新加天地图这层时，复制粘贴了高德那层的注释"webst + style=6"，忘了改
- 第 5 次踩这个坑了。以后复制的注释块、URL、参数块，**先检后走**

### Day 3 补充收尾

- WGS84 坐标打点要用 `fromLonLat()` 转 3857，不然经纬度被当米用，点飞到非洲
- 同一个 WGS84 点在不同坐标系底图上位置不同（小区内 vs 路边）→ 可视化层面的 589 米偏移

### Day 4 
GCJ-02 是什么、我是怎么纠偏的
GCJ-02 是火星坐标系，是国内商业地图（高德、腾讯）用的加密坐标系，它和GPS给的WGS84真实坐标之间差几百米，而且是非线性偏移，不能简单的加减修正，经过国测局算法加密的。

纠偏用的gcoord库，核心就一个函数transform(坐标，来源坐标系，目标坐标系)。比如我拿到一个WGS84坐标要在高德地图上显示，就调gcoord.transform([lng, lat], gcoord.WGS84, gcoord.GCJ02),转换后的经纬度再过fromLonLat打到地图上，就能精确落在正确位置。

我验证过，转换结果和高德坐标拾取器坐标只差2-4毫米，精度达标。

- 本质："底图"和"叠加层"是两个需求，选错域名 = 假底图

**坑 8：切换异坐标系底图，点偏移几百米——这是"预期行为"不是 bug**

- 点转成 GCJ-02 后：高德（GCJ-02）上精确 ✅ → 切到天地图（CGCS2000≈WGS84）就偏几百米 ❌
- 原因：跨系必偏（Day 1 规律第 N 次复现）
- 结论：**底图切换 = 坐标系切换，数据坐标系必须跟着底图走**。生产环境切换底图时，点位数据要么同时转换，要么底图都选同一坐标系
- 面试点："底图切换"话题的隐藏考点就是这句话

**图层分组意识（做对了，记录一下）**

- 注记层必须跟同坐标系的底图**同步显隐**：高德注记跟高德底图、天地图注记跟天地图底图
- 否则会出现"天地图底图 + 高德注记"混搭错位（又是跨系问题）

高德（GCJ-02）和天地图（CGCS2000）坐标系不同，所以纠偏后的点在高德坐标系上准确，切到天地图就偏几百米。生产环境选底图必须让底图坐标系和数据坐标系配套。
